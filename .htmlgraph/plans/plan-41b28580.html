Plan: 0.9 Job sourcing pipeline — Gmail-API + extensible parsers

Inbox-as-firehose: poll Gmail via direct API (cross-platform — no AppleScript / no MCP), route messages through a parser registry, normalize into a single JobCandidate type with provenance, dedup across sources, prescore against master, surface in CLI + web triage. Layered architecture: Source → Envelope → Parser → JobCandidate. Per-platform parsers reuse shared helpers (salary, time, location, URL canonicalization, dedup keys). Adding a new platform = one parser file + golden fixtures. MVP covers LinkedIn + JobRight; Indeed and Glassdoor land as later slices to prove the abstraction; RSS and ATS-scraper sources extend beyond email. Climatebase is treated as a first-class email source (slice 7) given the user's climate-sector career focus.

DesignPending

Problem

Job sourcing today is manual: the user reads two inboxes (LinkedIn alerts + JobRight digests) for ~25 unique candidates per day after dedup, copies a URL into `jobsmith apply`, and discards the rest. There's no persisted candidate store, no cross-source merge (same job from LinkedIn and JobRight creates two manual lookups), no prescoring against master, no triage rules (block companies / titles / keywords), no feedback loop from dismissals back to master.yaml. Validation pass already confirmed: LinkedIn canonical job URLs (`/jobs/view/<id>/`) and JobRight URLs (`jobright.ai/jobs/info/<hex>`) are publicly fetchable; LinkedIn emails have plaintext alternatives, JobRight emails are HTML-only (Gmail MCP surfaces neither HTML nor raw, hence the direct Gmail API decision). Inbox audit additionally surfaces alerts@climatebase.org ships HTML-only digests every 2-3 days with SendGrid-wrapped URLs — currently dropped silently because no parser exists.

Goals

  1. **Inbox → store** — Gmail messages from any registered job platform land in `job_candidates` automatically; user only triages, never copies URLs
  2. **Cross-platform** — runs on macOS / Linux / Windows / Docker / cron; no AppleScript, no Mail.app, no Claude session required
  3. **Extensible** — adding Indeed / Glassdoor / Wellfound is one parser file plus golden fixtures; the dispatcher and helpers do not change
  4. **Dedup-first** — same job sighted across multiple sources merges into one candidate row with provenance preserved; user makes one triage decision
  5. **Prescored top-N** — candidates ranked by reuse of `apply-fit-scorer` against master so the user only reviews the top 10 per day, not 25
  6. **Closed-loop triage** — dismissals (by company, title pattern, keyword) become master.yaml exclusion suggestions reviewed by the user
  7. **Halt over fabricate inherited** — no auto-apply; triage = saved / dismissed / queued for /apply pipeline
  8. **Climate-sector source coverage** — Climatebase emails ingested first-class with a SendGrid-redirect resolver that doubles as a reusable helper for any tracker-wrapping email source.

Constraints

  • Cross-platform: do NOT depend on AppleScript / Mail.app / IMAP single-vendor / MCP runtime. Direct Gmail API + OAuth refresh-token flow only.
  • Per-source PARSERS are pure functions: input = parsed `email.message.Message` envelope, output = `ParseResult(candidates, alert_metadata, warnings)`. No side effects, no I/O.
  • Shared HELPERS in `src/jobsmith/sources/helpers/` are the reusable core. Parsers compose helpers; parsers do not duplicate parsing logic.
  • Master YAMLs stay read-only. The triage feedback loop SUGGESTS additions to a separate `private/triage-rules.yaml`; it never writes assets/content/*.yml.
  • Inherits 0.6 spike Option C (skip PocketBase). All persistence in the existing `private/jobsmith.db` SQLite.
  • Dedup is two-stage: source-specific external_id (when present), then `(normalized_company, normalized_title, normalized_location)` SHA1 fallback for cross-source merge.
  • Out of scope: auto-applying, sourcing from Twitter/LinkedIn DMs, auto-master-edits, multi-user concurrency, hosted/SaaS.

#3 Parser protocol + shared helpers (the reusable core) The foundational abstraction. L Med Promoted Pending
What

The foundational abstraction. Adding a new platform later (Indeed, Glassdoor) is mechanical because of this slice.

src/jobsmith/sources/protocol.py:

@dataclass
class Envelope:
    envelope_id: str           # Gmail message id (or RSS entry id later)
    source_kind: Literal['email', 'rss', 'http']
    received_at: datetime
    headers: dict[str, str]    # Subject, From, Date, ...
    plaintext_body: str | None
    html_body: str | None
    raw_bytes: bytes | None

@dataclass
class ParseResult:
    candidates: list[JobCandidate]
    alert_metadata: AlertMetadata   # search keyword, alert kind (digest/instant)
    parser_warnings: list[str]      # for golden-test regression detection

class JobAlertParser(Protocol):
    name: str                       # 'linkedin', 'jobright', ...
    parser_version: str
    sender_patterns: list[re.Pattern]
    subject_patterns: list[re.Pattern]   # optional secondary check

    def matches(self, env: Envelope) -> bool: ...
    def parse(self, env: Envelope) -> ParseResult: ...

def register_parser(parser: type[JobAlertParser]) -> None: ...
def parse_envelope(env: Envelope) -> ParseResult: ...   # iterates registry, picks first match

src/jobsmith/sources/helpers/:

  • salary.py:parse_salary(text) — handles $160K/yr - $200K/yr, $70/hr - $85/hr, $80,000 - $140,000, €60K - €80K. Returns SalaryRange | None.
  • time_parse.py:parse_relative_time(text, *, ref) — handles "5 hours ago", "20 minutes ago", "yesterday", "just posted", "2 days ago", "3 weeks ago".
  • location.py:normalize_location(loc) — returns NormalizedLocation with city, state, country, remote_policy. Handles "NYC Metro Area, US", "Remote", "Hybrid - Austin, TX".
  • company.py:normalize_company_name(name) — strips Inc/LLC/Ltd/Corp/Co., casefolds, trims; for dedup.
  • url.py:normalize_url(url, *, source) — per-source canonicalization. linkedin: /jobs/view/<id>/. jobright: /jobs/info/<hex>. indeed: /viewjob?jk=<key>. glassdoor: strip s and pos params.
  • dedup.py:compute_dedup_key(company, title, location) — SHA1 of normalized tuple; deterministic.
  • html.py:extract_anchors(html) — list of (text, href) tuples. Reuses BeautifulSoup4.
  • email_envelope.py:envelope_from_rfc822(raw) — builds Envelope from RFC822 bytes. Walks MIME tree, extracts plaintext_body and html_body regardless of structure (multipart/alternative, html-only, plaintext-only).

#7 Climatebase email parser + SendGrid redirect helper Climatebase is the user's highest-priority career-target source (climate M Med Promoted Pending
What

Climatebase is the user's highest-priority career-target source (climate sector focus). Inbox audit confirmed: alerts@climatebase.org ships "New jobs matching your profile" emails every 2-3 days, HTML-only (~50KB), ~5-15 jobs per email. URLs are wrapped through SendGrid click-tracking (https://u23036105.ct.sendgrid.net/ls/click?upn=<token>); the canonical Climatebase URL or the employer ATS URL is reachable only by following the redirect.

New shared helper

src/jobsmith/sources/helpers/redirect.py:

  • resolve_redirect(url: str, *, max_hops: int = 5, timeout: float = 10.0) -> str — uses httpx with follow_redirects=False in a manual loop, walks the Location header chain, returns the final non-tracked URL.
  • Recognized trackers (return final URL, not the tracker URL): SendGrid (sendgrid.net/ls/click), Mailgun (email.mailgunhq.com), ActiveCampaign (activehosted.com/proc.php?ix=), generic 30x chains.
  • Honors per-tracker timeouts; on failure returns the original URL with a flag so callers can mark the candidate low_confidence_url.
  • This helper is part of the reusable core — JobRight, Glassdoor, and any future tracker-wrapping source can use it.

Climatebase parser

src/jobsmith/sources/parsers/climatebase_email.py:

  • name = 'climatebase', parser_version = '1.0.0'
  • sender_patterns = [re.compile(r'^alerts@climatebase\.org$')]
  • subject_patterns = [re.compile(r'New jobs matching')]
  • parse(env) walks env.html_body with BeautifulSoup:
    • Each job card has: company logo, company name, role title, location, posted-time text, "View Job" anchor (SendGrid-wrapped)
    • Extract title, company, location, posted-time using the slice-3 helpers (parse_relative_time, normalize_location, normalize_company_name)
