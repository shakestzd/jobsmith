Description

The DB is documented as the source of truth for apply_state, but reconcile_canonical_slug only reads applications/*/.apply-state/jd-parsed.json. Prompts therefore still require specialists to mirror DB state to disk, producing extra tool work and Write-before-Read failures in agent transcripts, and creating a second state source at the most important boundary. Durable fix: make slug reconciliation DB-first using apply_state rows scoped by run/start time or run_id, keep any filesystem mirror as derived compatibility output, then update gather/JD-parser prompts and tests so a DB-only jd-parsed row can rekey successfully.
