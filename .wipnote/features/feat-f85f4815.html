Introduce a user-level settings store (TOML at the OS config dir, e.g. ~/.config/jobsmith/settings.toml; resolved via platformdirs) holding a `repo_root` key. Centralize ALL repo-root resolution in paths.py `repo_root_for()` — today it is a one-line wrapper over find_config(cwd) (paths.py:14-19); make it the multi-tier resolver with documented precedence: 1. explicit --repo-root CLI flag (new global option) 2. JOBSMITH_REPO_ROOT env var (existing path) 3. settings.toml repo_root 4. find_config(cwd) walk-up (existing fallback) 5. error with actionable message if none resolve to a dir containing .apply-config.yaml Add `jobsmith config set-repo-root `, `jobsmith config show`, `jobsmith config clear-repo-root`. Settings module is new (src/jobsmith/settings.py). Because core/paths.py also calls find_config(cwd) at lines 26/167/176/196 and _cli_apply.py threads cwd into those helpers, both are in scope so every read funnels through the one resolver.
