Description

New adapters that turn job-alert emails into postings: (a) Gmail — read-only API (google-api-python-client + google-auth-oauthlib, NEW deps declared in pyproject.toml; creds/token via .env) searching the alert senders configured in sourcing.yaml (LinkedIn, Indeed, Glassdoor, etc.), parsing each alert's job entries (title, company, location, link) into normalized postings with source=gmail/; (b) Mail.app — same parsers against the local store via the EXISTING installed mail-app CLI (external tool, already on this machine) for senders not in Gmail; (c) manual — `jobsmith source add ` records pasted LinkedIn job IDs/URLs as postings (source=manual/linkedin). Parsing is template-based per sender over a NEW fixture corpus (none exists in either repo — authored from real alert emails); an unparseable alert is recorded as degraded, never crashes the run. Email postings carry snippets only; full JD text is fetched at promote time via the existing httpx/Playwright fetcher (no scraping in the daily run).
