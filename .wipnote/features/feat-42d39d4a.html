Description

Compute an application_fingerprint per JD from its normalized requirement set + normalized text (slice-2). On a new JD, look up application_fingerprints; if a prior JD is a near-duplicate above the (config) dedup threshold, reuse its jd-parsed.json and fit-score.json (read via src/jobsmith/_state_readers.py:36 and :44) instead of re-running apply-jd-parser / apply-fit-scorer. Below threshold, run normally and store the new fingerprint. This is the FUZZY tier above llm_cache's exact jd_hash keying -- it catches reposts/edited JDs that llm_cache misses.
