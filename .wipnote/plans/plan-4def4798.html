Plan: Sourcing-to-apply funnel: crawler port, email ingestion, postings inbox, funnel dashboard

Couple job retrieval to the jobsmith apply pipeline so the whole funnel is tracked in one system. The shakestzd Path-B sourcing pipeline (plan-9c5e0d04: ATS crawler, scoring, Notion inbox, headless-claude launchd run) proved discovery works but dead-ended in Notion, ran the crawl inside a fragile headless agent (max-turns / permission stalls — silently failing since early May), and is now disabled. This plan ports the proven pieces INTO jobsmith: deterministic `jobsmith source run` (no agent turns), ATS adapters + NEW email-alert ingestion (Gmail + Mail.app), LLM rescoring only for the shortlist, a ranked Postings inbox in the web UI with one-click promote-to-apply, launchd scheduling with VISIBLE run health, and a funnel dashboard (sourced -> queued -> applied -> outcome with conversion). NOTE for reviewers: crawling (slices 2-3) is deterministic Python; the LLM stage (slice 4) is post-crawl, capped to the shortlist, and skippable — the daily schedule cannot die on agent turns by construction. OLD DATA: we start fresh — the 1,944 previously-seen roles and the Notion inbox rows are stale (mostly expired postings from May) and are intentionally NOT migrated; Notion data is left in place read-only.

DesignPending

Problem

Job retrieval is disconnected from application tracking. The existing sourcing pipeline (shakestzd private/scripts: source_jobs.py + greenhouse/lever/ashby/ hn_whos_hiring/climatebase adapters, 23 sources, 1,944 roles seen) wrote to a Notion inbox nobody works from, ran the crawl inside headless `claude --print` (which died on max-turns and permission prompts, silently, exit 0), and never ingested the user's email job alerts. Meanwhile jobsmith owns the actual apply work (fit-scorer, reuse layer, UI) but every application starts by hand-pasting one URL. Result: the user disabled sourcing, and there is no view of the funnel from discovery to outcome.

Goals

  1. One command, no agent: deterministic `jobsmith source run` crawls boards + email alerts, dedupes, fast-scores; LLM (agent-sdk fit-scorer) rescores only the shortlist.
  2. Postings land in a ranked inbox in the jobsmith web UI; one click promotes a posting into the apply pipeline with provenance linked.
  3. Whole-funnel tracking: sourced -> queued -> applied -> interview/offer/rejected with per-stage conversion and per-source yield.
  4. Scheduled daily via launchd with VISIBLE run health (UI banner + doctor check) — a failed or empty run is noticed the same day, not after 5 weeks.
  5. Retire the Notion writer and the headless-claude morning-sourcing path.

Constraints

  • Crawling is plain Python — no LLM turns in the crawl loop (the max-turns failure class must be impossible by construction).
  • No LinkedIn scraping (auth-wall/ToS): LinkedIn arrives via alert-email parsing and manual paste/batch only.
  • Reuse proven code: port the shakestzd adapters/scoring rather than rewrite; reuse jobsmith's existing apply endpoints, fit-scorer agent, and UI patterns.
  • Local-first single-tenant; secrets stay in .env; Gmail read-only scope.
  • Start fresh: no migration of the old pipeline's 1,944 roles / Notion rows / sourcing-state.yaml (stale May data); explicitly out of scope.

Funnel uses the APPLICATION's fit score post-promotion (triage score is pre-funnel ranking only). Nav wiring: ViewName (types.ts) + chrome.tsx sidebar, same as slice-5.

Why

'Track the whole pipeline' means answering 'is sourcing working and which sources are worth it' at a glance — counts + conversion + per-source yield is exactly that (user's chosen funnel-view option).
