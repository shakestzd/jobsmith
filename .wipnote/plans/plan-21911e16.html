DesignPending

Problem

jobsmith's apply pipeline (gather -> draft -> render) is hardwired to the Claude Code CLI: src/jobsmith/headless.py builds a `claude -p` command (_build_command, ~241-294) with --system-prompt-file/--allowedTools/--agents and spawns it via subprocess.Popen (run_phase, ~415), parsing stream-json events incl. text markers <<PHASE_COMPLETE>>/<<PHASE_FAILED>> and dispatching specialist sub-agents that each request a Claude tier (haiku/sonnet/opus). plan-938f735b made CHAT + sourcing SCORING pluggable but scoped OUT this agentic harness. The user wants the WHOLE pipeline runnable by a local/open model so jobsmith is not Claude-locked.

Goals

  1. Run the full apply pipeline end-to-end on a local gemma-4 model, reusing the Claude Code harness unchanged (no specialist/tool re-architecture).
  2. Drive it by pointing `claude -p` at a local Anthropic-native MLX server (vllm-mlx) that serves gemma-4 with real tool_use blocks — selected via the existing `llm` config. No translation proxy.
  3. Preserve the cloud Claude path as the default/backward-compatible backend; the local path is opt-in.
  4. Prove tool-calling fidelity first (spike) before building plumbing — de-risk that a 4B gemma can complete the agentic loop AND that vllm-mlx carries tool_use for all requested Claude tiers.

Constraints

  • Do not regress the existing `claude -p` cloud path (default behavior unchanged when the local backend is not selected).
  • Tool use under the local model must work end-to-end — WebFetch/Read/Write/Bash + the claude-in-chrome Chrome-render fallback (feat-2c81da71). The engine MUST support tool calling (mlx_lm.server does NOT — that is why vllm-mlx is chosen).
  • Use the current Claude Code env var ANTHROPIC_DEFAULT_HAIKU_MODEL (ANTHROPIC_SMALL_FAST_MODEL is deprecated). Apple Silicon (MLX). Avoid LiteLLM 1.82.7/1.82.8 (malware).

What
